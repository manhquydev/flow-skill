# Phase 3: A2 pack install rehearsal + parity

## Overview
Prove the publishable artifact on every PR, credentialless: `npm pack` the wrapper, install the
tarball into a temp skill home, drive the installed skill (`tests/e2e-installed-drive.sh`), and
verify the synced skill tree hasn't drifted from the canonical `skills/flow/`.
Pattern source: dsh credentialless pack + `verify-packed-install` byte-pinning
(`research-260814-0915-deepseek-tech-stack.md` §5.1, §6.11).

## Requirements
- Functional: rehearsal job on every PR, ubuntu lane only (Windows budget protection); no secrets,
  no publish; feeds `all-checks-passed` from Phase 2.
- Non-functional: rehearsal reuses existing scripts — no parallel logic (DRY). `RELEASE_CHECKLIST.md:94`
  is the `npm pack --dry-run` **size audit**, not an install+drive. The working installed-drive
  contract is `azure-pipelines.yml:71-73`: `test -f` the installed `flow.sh`, then
  `bash tests/e2e-installed-drive.sh "$RUN"`. `e2e-installed-drive.sh:5` takes positional `$1` =
  runner path and **defaults to the repo tree** — there are no skill-home env knobs.

## Architecture
- Sync parity fact: `npm-wrapper`'s skill tree is generated by `npm-wrapper/scripts/sync.mjs` from
  `../skills/flow`, and `npm-wrapper/.gitignore` ignores `skills/` (materialized at prepack, not
  tracked) — so a `git diff` parity branch checks nothing (red-team finding). **Parity mechanism =
  tarball extract-and-compare:** `npm pack` → extract → `--compare` extracted
  `package/skills/flow` against repo `skills/flow` via the shared JS predicate (`shouldShip`
  `:68-74` / copy `filter` `:57-63` — twins; invoked through `--compare` **after an argv
  short-circuit**, not a bash reimplementation and not an unfiltered `diff -r`).
- New CI job `pack-rehearsal` in `ci.yml`: checkout → node setup (≥22.14, same floor as
  `npm-wrapper/package.json` `engines`) → **`cd npm-wrapper && npm pack`** (prepack already runs
  `sync.mjs`; tarball name is `manhquy-flow-skill-*.tgz` from `@manhquy/flow-skill`) → extract
  tarball → `--compare` extracted `package/skills/flow` vs repo `skills/flow` via the **same JS
  predicate** as `shouldShip` (`sync.mjs:68-74`; the copy `filter` at `:57-63` is the twin —
  keep them identical). `shouldShip` is **not exported** today — do **not** reimplement the
  exclusion list in bash (Phase 7 will add `eval/replay/` and a forked bash filter would
  false-fail parity). Required: add a `--compare <extracted> <repo>` mode to `sync.mjs` and
  have `scripts/pack-rehearsal.sh` call it. Do **not** write a sibling that imports
  `shouldShip` (it is not exported). Extracting the predicate into a side-effect-free module
  that both the default sync path and `--compare` import is allowed.
  `npm pack` nests files under `package/` (`package.json` `files` includes `skills/`), so
  `--compare` walks **extracted `package/skills/flow`**, not a tarball-root `skills/flow/`.
  Then `npm i --no-audit --no-fund --ignore-scripts --prefix <tmp> ./manhquy-flow-skill-*.tgz`
  → installer **required** invocation:
  `<tmp>/node_modules/.bin/flow-skill --yes --project --dir "$DEST"`
  (matches `npm-wrapper/src/help.mjs:21` / `cli.mjs:128`: writes
  `$DEST/.claude/skills/flow` only — not `~/.claude`). Pin one path, azure-shaped:
  `RUN="$DEST/.claude/skills/flow/runner/flow.sh"`; `test -f "$RUN"`;
  `bash "$ROOT/tests/e2e-installed-drive.sh" "$RUN"`.
  There is no `$INSTALLED` variable. Zero-arg e2e invoke is forbidden.
  Do **not** drive rehearsal via repo `install.sh` — that copies the checkout, not the tarball.
  **`--compare` cannot be a flag added below today's sync body.** `sync.mjs:43-64` runs
  `rmSync`+`cpSync` at load with no argv gate; `shouldShip` is not exported. Required: an
  early `process.argv` branch (or extract the predicate into a side-effect-free module)
  **before** any copy. Drop the "sibling that imports `shouldShip`" option.
- Add `pack-rehearsal` to Phase 2's `needs` list of `all-checks-passed`.

## Implementation Steps
1. Read `tests/e2e-installed-drive.sh:5` and `azure-pipelines.yml:71-73` — the contract is
   positional `$1` = installed runner, not a "home" env knob.
2. Write `scripts/pack-rehearsal.sh`: `set -eu`; `ROOT` = repo root (script lives in
   `scripts/`). Temp dirs via `mktemp -d`. Pack from `"$ROOT/npm-wrapper"` (tarball lands
   there). Extract; `--compare` extracted `package/skills/flow` vs `"$ROOT/skills/flow"` via
   `"$ROOT/npm-wrapper/scripts/sync.mjs"` (argv branch before copy — see Architecture).
   Install tarball from the pack dir to temp `--prefix` with `--ignore-scripts`; dry-run
   JSONL then `--yes --project --dir "$DEST"`; `RUN="$DEST/.claude/skills/flow/runner/flow.sh"`;
   `test -f "$RUN"`; `bash "$ROOT/tests/e2e-installed-drive.sh" "$RUN"`; assert `$RUN` is not
   the checkout `skills/flow/runner/`. Cleanup trap. Merge-order note: this phase and Phase 5
   both touch `npm-wrapper/RELEASE_CHECKLIST.md` — land 3 before 5.
3. Wire CI job (ubuntu-latest only) + `needs` update.
4. Out of wave-1 (research A2 optional follow-on — do not implement here): idempotent-publish
   helper. File as a post-wave card. A2 success is pack-rehearsal + tarball parity only.
5. Verify on a PR whose **base is `master`** (this branch's pushes do not run GHA); then a
   deliberate 1-byte drift in the packed tree must fail the parity step (evidence link), revert.
